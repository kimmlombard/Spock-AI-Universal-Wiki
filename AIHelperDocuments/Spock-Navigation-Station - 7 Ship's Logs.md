### 1. Overview & Architecture
The **"7 Ship's Logs"** panel is a tabbed database viewer integrated into the PyQt6-based suite windows. It acts as a visual window into the ship's primary SQLite database, `ship_computer.db`. 

* **Source Location**: The panel is constructed by the factory function `build_ships_logs_panel(theme, db_path)` located in `ScienceStation/ships_logs.py` (referenced in `D:\Spock-Onboarding\NavigationStation\app.py` and `D:\Spock-Onboarding\ScienceStation\app.py`).
* **Target Database**: It directly queries `SHIP_COMPUTER_DB` (defined in `spock_shell.paths` as `D:\Spock-Onboarding\ship_computer.db`).
* **Call Flow**:
  1. The user clicks the **"7 Ship's Logs"** item in the left-hand navigation list (`nav_steps` in `NavigationStation/app.py`).
  2. This triggers the `_show_ships_logs()` method:
     ```python
     def _show_ships_logs(self) -> None:
         """Captains Log / Agents Queue / Documents / Quarantine, tabbed."""
         if self._logs is None:
             self._logs = build_ships_logs_panel(self.theme, SHIP_COMPUTER_DB)
             self.stack.addWidget(self._logs)
         select = getattr(self._logs, "select_table", None)
         if callable(select):
             select("documents")
         self.show_center(self._logs)
     ```
  3. The panel is lazily instantiated, added to the central `QStackedWidget`, and the view is automatically focused on the `"documents"` table by default.

### 2. Detailed Breakdown of Options (Tabs)
The panel is divided into four primary tabs, each mapping to a critical table or state within `ship_computer.db`:

#### A. Documents Tab (`documents` table)
* **Purpose**: Displays the files that have been successfully scanned, parsed, and ingested into the knowledge base.
* **Content**: Shows file paths, file sizes, timestamps, and language/extension classifications.
* **Usage**: This is the default view. It allows operators to verify which codebase files (e.g., `.py`, `.ts`, `.rs`, `.go`) are currently indexed and available for the RAG (Retrieval-Augmented Generation) pipeline and the "Ask AI" / "Deep Dive" tools.

#### B. Captains Log Tab (`captains_log` table)
* **Purpose**: Displays system events, audit trails, and operational logs generated by the ship's computer and background agents.
* **Content**: Chronological rows detailing agent actions, system startups, errors, and stardates.
* **Usage**: Used for debugging and auditing. For example, when the Wiki Agent runs or when a model is launched, entries are written here. (This table is also exposed to external LLMs via the MCP tool `spock_captains_log` in `scripts/mcp_spock_server.py`).

#### C. Agents Queue Tab (`agent_queue` table)
* **Purpose**: Monitors the background task queue managed by the system's automated agents (such as the Wiki Agent).
* **Content**: Displays pending, active, completed, or failed jobs, along with their payloads and priority levels.
* **Usage**: Essential for tracking asynchronous ingestion tasks, long-running codebase scans, or external repository fetches. (Exposed to external LLMs via the MCP tool `spock_queue`).

#### D. Quarantine Tab (`quarantine` table/status)
* **Purpose**: Isolates files that failed validation, safety checks, or parsing during ingestion.
* **Content**: Lists files that were skipped or flagged, along with error messages or reasons for quarantine (e.g., encoding issues, size limits, or security policies).
* **Usage**: Allows developers to identify why certain files are missing from the RAG index and take corrective action (such as adjusting filters or fixing file encodings).

### 3. Usage & Operational Integration

* **Real-Time Monitoring**: The panel provides a "Refresh" mechanism (often tied to database change events or manual refresh buttons) to query the SQLite database and update the table views dynamically.
* **Wiki Agent Integration**: When running a codebase scan via **"6 Run Wiki Scan"** (`wiki_agent.py`), files are processed in real-time. Operators can switch to **"7 Ship's Logs"** to watch the `documents` count grow, monitor the `agent_queue` process tasks, and check the `captains_log` for any warnings or completion stardates.
* **MCP & Headless Alignment**: The tables viewed in this GUI panel are identical to the data structures queried by the headless command-line tools and the MCP server (`scripts/mcp_spock_server.py`). This ensures that whether you are looking at the PyQt6 GUI or querying Spock through an IDE (like Cursor/VS Code via MCP), you are seeing the exact same state of the ship's computer.
